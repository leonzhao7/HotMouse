# 多阶段利用链

## 何时使用

已有一个确认可用的原语，但目标不在当前权限范围内；或题面明确给出多个主机、角色、账户、服务。与 web-exploit、cloud-exploit、binary-pwn 等专项技能组合使用。

## 每一跳的固定记录

| 字段 | 要记录的事实 |
|---|---|
| 当前身份 | 用户、角色、容器、云主体及权限来源 |
| 可用原语 | 读、写、执行、代理请求、身份切换中的哪些已验证 |
| 可达范围 | 题目授权的主机、网段、API 和文件范围 |
| 目标差距 | 还需要哪项权限或哪条可达路径 |
| 下一跳 | 一条可验证的假设及成功/失败判据 |

把记录写入当前题的 memory/<题号>.tree.md；已否证的路径写入 deadends.md。敏感凭据只记必要的来源和用途，不在报告中复制原文。

## 推进顺序

1. 从已有原语查当前题的目标位置与身份边界，先复用已成功的读、写、执行或会话能力。
2. 识别当前身份能访问的配置、服务账户、内部 API、挂载和网络路径；每一步先确认权限与可达性。
3. 画出节点和有证据的边：入口 → 原语 → 身份/立足点 → 下一资源 → 目标。猜测用待验证标记，不当成已建立的边。
4. 对最短且可回退的下一跳做一次验证；记录返回、角色变化和限制。失败时换假设或观测通道。
5. 新身份或立足点确认后，重新枚举该身份实际可访问的目标资源；需要时转 cloud-exploit 或 auth-attack。

## 边界

只在当前题 Origin 明确授权的资产和网段内探测。沿用 PI 系统规则的速率、工作区、无外部回连和由 driver 提交 flag 的约束。已有本地 playbook 可作参考；其中的命令先用 command -v 核对，仅使用镜像已安装的 ssh、socat、curl 等工具，并核对题目地址与范围。

## 输出

一条有证据的攻击路径；每条边的验证结果、未满足的前提和下一步。不要把阶段性访问等同于最终目标完成。
